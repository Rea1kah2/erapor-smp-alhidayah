2. LATAR BELAKANG & TUJUAN SISTEM
--------------------------------------------------------------------------------
A. Masalah Sistem Lama (As-Is):
   1. Pencatatan Terpisah: Guru menginput nilai secara manual (kertas/Excel non-terpusat).
   2. Duplikasi Kerja: Wali kelas dan Tata Usaha (TU) harus merekap ulang data
      satu per satu yang memakan waktu dan tenaga.
   3. Human Error: Rawan kekeliruan salah input atau perhitungan nilai akhir (NA).
   4. Hambatan Arsip: Arsip nilai fisik menyulitkan penelusuran riwayat akademik terdahulu.

B. Solusi Sistem Baru (To-Be):
   1. Terintegrasi: Alur penginputan nilai, rekapitulasi, perhitungan ranking, hingga
      pencetakan rapor terpusat dalam satu aplikasi web.
   2. Kalkulasi Otomatis: Nilai Akhir (NA), predikat kelulusan (KKM), dan ranking kelas
      dihitung secara otomatis menggunakan formula standar.
   3. Aksesibilitas Multi-Role: Dapat diakses kapan saja oleh Admin/TU, Guru,
      Wali Kelas, Siswa, dan Orang Tua secara transparan dan akuntabel.
   4. Siap Cetak Digital: Ekspor/Cetak lembar rapor standar format A4 kedinasan
      lengkap dengan Kop Surat SMP Al-Hidayah dan kolom pengesahan.

5. HAK AKSES & PERAN PENGGUNA (ROLE PRIVILEGES)
--------------------------------------------------------------------------------
Sistem mendukung 5 peran pengguna dengan mekanisme otentikasi berbasis Token (JWT):

1. Administrator / Staf TU (Role: ADMIN)
   • Akses penuh dashboard analitik & statistik master data sekolah.
   • Manajemen data guru (NIP, nama, email, akun login).
   • Manajemen data siswa (NISN, kelas, akun login, relasi orang tua).
   • Manajemen data akademik (Tingkat jenjang kelas 7, 8, 9, dan penugasan Wali Kelas).
   • Manajemen mata pelajaran kurikulum dan standar KKM.
   • Supervisi rekapitulasi seluruh kelas dan cetak rapor semua siswa.

2. Guru Mata Pelajaran (Role: GURU)
   • Mengakses daftar mata pelajaran yang diampunya.
   • Menginput, mengedit, dan menyimpan nilai Tugas, UTS, dan UAS siswa per kelas.
   • Melihat visualisasi status ketercapaian KKM siswa.

3. Wali Kelas (Role: GURU yang memiliki penugasan Wali Kelas / Opsi A)
   • Otomatis mendeteksi kelas binaan di menu khusus "Rekap & Wali".
   • Memantau rekapitulasi nilai kumulatif seluruh mata pelajaran di kelas binaannya.
   • Kalkulasi otomatis Nilai Rata-rata dan Peringkat Kelas (Ranking 1..N).
   • Menginput dan memperbarui komponen Catatan Rapor:
     - Presensi: Hari Sakit (S), Izin (I), Tanpa Keterangan / Alfa (A).
     - Sikap Spiritual: Predikat (A/B/C/D) dan deskripsi pembinaan ibadah/toleransi.
     - Sikap Sosial: Predikat (A/B/C/D) dan deskripsi kesantunan, kedisiplinan, peduli.
     - Ekstrakurikuler: Daftar kegiatan (Pramuka Wajib, dsb.), predikat, dan keterangan.
     - Catatan Wali: Pesan bimbingan dan motivasi siswa.
     - Kenaikan Kelas: Status keputusan kenaikan kelas (khusus semester Genap).
   • Mencetak lembar rapor resmi siswa dalam format A4.

4. Siswa (Role: SISWA)
   • Melihat profil diri, NISN, kelas, dan nama guru wali kelas.
   • Membuka menu "Rapor Saya" untuk melihat transparansi capaian nilai mata pelajaran.
   • Memeriksa status ketuntasan KKM, rekap presensi, dan catatan sikap secara mandiri.
   • Meninjau dan mengunduh pratinjau lembar cetak rapor pribadi (PDF).

5. Orang Tua / Wali Murid (Role: ORTU)
   • Terhubung secara relasional ke data akun anak (siswa).
   • Memantau perkembangan akademik anak secara real-time.
   • Membuka evaluasi nilai akhir, presensi (sakit/izin/alfa), dan catatan bimbingan guru.
   • Mencetak lembar rapor resmi anak dari rumah kapan saja.


6. FORMULA & ATURAN LOGIKA PENILAIAN (GRADING BUSINESS LOGIC)
--------------------------------------------------------------------------------
A. Pembobotan Nilai Akhir (NA):
   • Tugas / Harian  : Bobot 40% (0.4)
   • Nilai UTS       : Bobot 30% (0.3)
   • Nilai UAS       : Bobot 30% (0.3)

   Rumus:
   NA = (Tugas * 0.4) + (UTS * 0.3) + (UAS * 0.3)

   *Catatan: Sistem secara cerdas menangani kondisi nilai parsial. Jika komponen
    belum lengkap terisi, pembagian dilakukan proporsional berdasarkan bobot yang ada.

B. Skala Predikat & Kriteria Ketuntasan Minimal (KKM):
   Standar KKM default adalah 75.0 (dapat disesuaikan per mata pelajaran).
   • Nilai Akhir >= 90         : Predikat "A" (Sangat Baik)
   • Nilai Akhir >= 80 s/d 89  : Predikat "B" (Baik)
   • Nilai Akhir >= KKM s/d 79 : Predikat "C" (Cukup / Tuntas KKM)
   • Nilai Akhir < KKM         : Predikat "D" (Kurang / Perlu Remedial)

C. Perhitungan Peringkat Siswa (Ranking):
   • Rata-Rata Siswa = (Jumlah Nilai Akhir Semua Mapel Dinilai) / (Jumlah Mapel Dinilai)
   • Peringkat kelas diurutkan menurun (descending) dari Rata-Rata tertinggi ke terendah.


7. STRUKTUR DATABASE (PRISMA SCHEMA)
--------------------------------------------------------------------------------
Database terdiri dari tabel-tabel terelasi berikut:

1. User
   - id          : String (UUID, Primary Key)
   - email       : String (Unique)
   - password    : String (Hash bcryptjs)
   - role        : String ("ADMIN", "GURU", "SISWA", "ORTU")
   - createdAt   : DateTime

2. Guru
   - id          : String (UUID, Primary Key)
   - nip         : String (Unique, Nullable)
   - nama        : String
   - userId      : String (Foreign Key -> User.id)
   - kelasWali   : Relasi 1-to-1 ke Kelas (menjadi Wali Kelas)
   - mapel       : Relasi 1-to-Many ke Mapel (mengajar mapel)

3. Siswa
   - id          : String (UUID, Primary Key)
   - nisn        : String (Unique)
   - nama        : String
   - kelasId     : String (Foreign Key -> Kelas.id, Nullable)
   - userId      : String (Foreign Key -> User.id)
   - ortuId      : String (Foreign Key -> Ortu.id, Nullable)
   - nilai       : Relasi 1-to-Many ke Nilai
   - catatanRapor: Relasi 1-to-Many ke CatatanRapor

4. Ortu
   - id          : String (UUID, Primary Key)
   - nama        : String
   - userId      : String (Foreign Key -> User.id)
   - anak        : Relasi 1-to-Many ke Siswa

5. Kelas
   - id          : String (UUID, Primary Key)
   - nama        : String (Contoh: "VII-A", "VIII-B", "IX-1")
   - tingkat     : Int (7, 8, 9 - Jenjang SMP)
   - waliId      : String (Foreign Key -> Guru.id, Unique, Nullable)
   - siswa       : Relasi 1-to-Many ke Siswa

6. Mapel
   - id          : String (UUID, Primary Key)
   - nama        : String (Contoh: "Matematika", "Bahasa Indonesia", "IPA")
   - kkm         : Float (Default: 75.0)
   - guruId      : String (Foreign Key -> Guru.id, Nullable)
   - nilai       : Relasi 1-to-Many ke Nilai

7. Nilai
   - id          : String (CUID, Primary Key)
   - skor        : Float (Skor nilai angka 0 - 100)
   - jenis       : String ("TUGAS", "UTS", "UAS")
   - semester    : String ("GANJIL", "GENAP")
   - tahunAjaran : String (Contoh: "2025/2026")
   - siswaId     : String (Foreign Key -> Siswa.id, Cascade Delete)
   - mapelId     : String (Foreign Key -> Mapel.id, Cascade Delete)
   - Constraint  : @@unique([siswaId, mapelId, jenis, semester, tahunAjaran])

8. CatatanRapor
   - id                 : String (UUID, Primary Key)
   - semester           : String ("GANJIL", "GENAP")
   - tahunAjaran        : String ("2025/2026")
   - sakit              : Int (Default: 0)
   - izin               : Int (Default: 0)
   - alfa               : Int (Default: 0)
   - sikapSpiritual     : String ("A", "B", "C", "D")
   - deskripsiSpiritual : String (Teks deskripsi ketaatan ibadah)
   - sikapSosial        : String ("A", "B", "C", "D")
   - deskripsiSosial    : String (Teks deskripsi etika sosial)
   - ekskul             : Json ([{ nama, predikat, keterangan }])
   - catatanWali        : String (Catatan motivasi dan bimbingan)
   - statusKenaikan     : String (Nullable, contoh: "Naik ke Kelas VIII")
   - siswaId            : String (Foreign Key -> Siswa.id, Cascade Delete)
   - Constraint         : @@unique([siswaId, semester, tahunAjaran])


8. DAFTAR ENDPOINT BACKEND (REST API SPECIFICATION)
--------------------------------------------------------------------------------
Semua endpoint selain autentikasi wajib menyertakan Header:
Authorization: Bearer <TOKEN_JWT>

A. Autentikasi (`/api/auth`)
   • POST /api/auth/login
     Body: { email, password }
     Response: { token, role, user }
   • GET  /api/auth/me
     Response: Detail profil pengguna login beserta relasi perannya.

B. Master Data Administrator (`/api/master`)
   • GET  /api/master/stats        -> Statistik total guru, siswa, kelas, mapel.
   • GET  /api/master/guru         -> Daftar seluruh data guru.
   • POST /api/master/guru         -> Tambah data guru & buat akun login otomatis.
   • GET  /api/master/siswa        -> Daftar seluruh siswa beserta kelas & ortu.
   • POST /api/master/siswa        -> Tambah data siswa & buat akun login.
   • GET  /api/master/kelas        -> Daftar kelas beserta nama wali kelas.
   • POST /api/master/kelas        -> Tambah kelas (tingkat 7, 8, 9 & pilih wali).
   • GET  /api/master/mapel        -> Daftar mata pelajaran beserta guru pengampu & KKM.
   • POST /api/master/mapel        -> Tambah mata pelajaran & tentukan KKM.

C. Pengolahan Nilai (`/api/nilai`)
   • POST /api/nilai               -> Simpan / update skor nilai (TUGAS/UTS/UAS).
   • GET  /api/nilai/mapel         -> Ambil matriks nilai siswa per mapel & kelas.
   • GET  /api/nilai/saya          -> Ambil riwayat nilai siswa (khusus SISWA & ORTU).

D. Rekapitulasi & E-Rapor Wali Kelas (`/api/wali`)
   • GET  /api/wali/kelas-binaan   -> Ambil data kelas yang diampu oleh wali kelas.
   • GET  /api/wali/rekap          -> Ambil rekapitulasi nilai, rata-rata, dan ranking kelas.
   • POST /api/wali/catatan        -> Simpan presensi, nilai sikap, ekskul, dan catatan wali.
   • GET  /api/wali/rapor/:siswaId -> Ambil lembar rapor cetak lengkap untuk 1 siswa.

10. PANDUAN INSTALASI & MENJALANKAN SISTEM (SETUP GUIDE)
--------------------------------------------------------------------------------
A. Prasyarat Sistem:
   • Node.js (Minimal versi 18.x atau versi 20.x rekomendasi)
   • npm (versi 9.x ke atas)
   • Akses Internet untuk koneksi database PostgreSQL Neon Cloud

B. Langkah Menjalankan Backend:
   1. Buka terminal dan arahkan ke folder backend:
      $ cd backend
   2. Pastikan file `.env` sudah terisi dengan kredensial database & JWT:
      DATABASE_URL="postgresql://neondb_owner:npg_1T2XoWJvDrcL@ep-weathered-snow-a1w1a2qf-pooler.ap-southeast-1.aws.neon.tech/neondb?sslmode=require"
      JWT_SECRET="rahasia_siakad_smp_alhidayah_super_aman"
   3. Sinkronkan skema database Prisma:
      $ npx prisma db push
   4. Jalankan server backend (development mode):
      $ npm run dev
   5. Server akan aktif di: http://localhost:3001

C. Langkah Menjalankan Frontend:
   1. Buka tab terminal baru dan arahkan ke folder frontend:
      $ cd frontend
   2. Instal paket dependensi (jika belum pernah diinstal):
      $ npm install
   3. Jalankan server frontend:
      $ npm run dev
   4. Buka aplikasi pada browser:
      http://localhost:3000
